# 03 · 插件开发指南

> 目标：把这个「示例插件」变成「你的插件」。每一步都给出改哪里、怎么验证。
> 全程遵循 `agent.md` 约定：**每次改动收尾前执行 `npm run gate`**。

## 0. 先理解模板架构

```text
src/models（数据模型）
   ↓
src/services（业务：校验/清洗/事件）← ItemService
   ↓
src/services/stores（IItemStore 数据源抽象：JSON 文件 / 全局存储 / 可替换）
   ↑ 读写
src/providers（树视图 + Webview 表单面板）    src/webview（Schema 表单渲染器）
   ↑ 调用
src/commands（命令注册中心）← src/extension.ts（组装一切）
src/tasks（启动任务框架）  src/features（四个功能页面）
```

数据流是单向的：**界面 → ItemService → IItemStore**，任何变更通过 `onDidChangeItems`
事件自动刷新视图。你二创时大部分工作只发生在 `models` 和 `webview/formSchema.ts`。

## 1. 改成你的插件身份（package.json）

| 字段 | 说明 |
| --- | --- |
| `name` | 插件英文标识（npm 规则：小写+连字符） |
| `displayName` | 市场显示名（建议与界面品牌一致） |
| `publisher` | 你的发布者 ID（vsce 创建：`npx vsce login <id>`） |
| `repository` | 已指向本仓库，改成你的 fork 地址 |
| `icon` | 发布前补一张 128×128 PNG，然后加 `"icon": "media/icon.png"` |

界面品牌（侧边栏「CRUD Starter」、命令分类）在 `package.json` 的
`contributes.viewsContainers` / `commands[].category` 与 `src/constants.ts` 中，一并替换。

## 2. 改数据模型与表单（最常见的改动）

以给条目加一个「负责人 owner」字段为例，共三步：

1. **模型** `src/models/item.ts`：`Item` 与 `ItemDraft` 各加 `owner: string;`；
2. **表单 Schema** `src/webview/formSchema.ts` 的 `FORM_SCHEMA` 加一行：

   ```ts
   { key: 'owner', label: '负责人', type: 'text', placeholder: '选填' },
   ```

3. **完成**。表单渲染、取值、回填、校验全部自动生效——渲染器里没有任何业务字段特例。

字段类型可用：`text` / `textarea` / `select`（配 `options`）/ `tags` / `boolean`。
要新控件类型：在 `formHtml.ts` 的 `renderField()` 加一个 case。

> 迁移旧数据：`JsonFileStore.load()` 返回前补默认值即可。

## 3. 更换数据源（接 API / 数据库）

实现 `src/services/stores/itemStore.ts` 的接口即可：

```ts
export class ApiStore implements IItemStore {
  constructor(private readonly baseUrl: string) {}
  async load(): Promise<Item[]> {
    const res = await fetch(`${this.baseUrl}/items`);
    return res.json() as Promise<Item[]>;
  }
  async save(items: Item[]): Promise<void> {
    await fetch(`${this.baseUrl}/items`, {
      method: 'PUT',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(items),
    });
  }
}
```

然后在 `src/extension.ts` 的 `createStore()` 返回 `new ApiStore(...)`。
业务层、树视图、表单、四个功能页面**零改动**。数据量大时把 ItemService 的
「读-改-全量写」改成按 id 增删改。

## 4. 新增命令 / 视图（三处同步，缺一不可）

门禁第 4 步会校验三处的一致性：

1. `src/constants.ts`：`COMMAND` / `VIEW` 加 ID；
2. `package.json`：`contributes.commands` 声明；要出现在菜单就配 `menus`
   （`view/title` / `view/item/context` / `editor/context` / `explorer/context`，注意写 `when`）；
3. `src/commands/index.ts`：`register(COMMAND.xxx, callback)` 写实现。

> 记住右键菜单传参约定：`view/item/context` 收到 `(树节点元素, 多选集合)`，
> 树节点要用 `toItem()` 归一化成 `Item`。

## 5. 扩展启动任务（动作类脚本）

实现 `StartupTask` 接口（`id / title / run()`）并在 `src/tasks/taskRegistry.ts`
的 `TASKS` 数组注册——调度、异常降级、输出通道、「环境信息」视图展示全部自动生效。
内置 `environmentTask`（环境检测）是完整参考实现。

## 6. 质量门禁与测试

- **每次收尾**：`npm run gate`（协议见 `agent.md`）；
- **加业务逻辑时**：在 `src/test/extension.test.ts` 补 `suite`（现有 26 个用例可当模板，
  服务层用内存 Store 即可测，不碰文件系统）；
- **测 UI 逻辑**：树视图的分组/过滤、表单渲染都有现成用例可仿写。

## 7. 打包发布

```bash
npm i -g @vscode/vsce
vsce package        # 生成 .vsix（门禁通过再打包）
vsce publish        # 发布到市场（需 publisher 账号 + PAT）
```

核对清单：`publisher` 已改 ✓ / 128×128 图标 ✓ / `repository` 指向你的仓库 ✓ /
`npm run gate` 全绿 ✓。本地验证 .vsix：扩展面板 `…` → `从 VSIX 安装…`。

## 8. 推荐的文件阅读顺序

1. `agent.md`（约定）→ 2. `src/extension.ts`（组装全貌）→ 3. `src/models/item.ts` +
   `src/webview/formSchema.ts`（数据与表单）→ 4. `src/services/itemService.ts`（业务核心）→
   5. `src/providers/itemsTreeDataProvider.ts`（视图如何消费数据）→ 6. 挑一个
   `src/features/` 目录读完整链路。

调试方法详见 [02 · 开发与调试步骤](02-开发与调试步骤.md)。
